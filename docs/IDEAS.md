## 1. 보안 (완료됨)
`external_customers` 테이블에 `USING(true)` 정책이 걸려있어 로그인 없이 원장님 고객정보(이름·전화번호·주소)가 노출되는 상태를 발견. 전체 테이블 전수조사 결과 RLS가 꺼진 테이블이 60개 넘게 발견됨 (profiles, payment_intents, shipping_addresses, orders, bookings, settlements 등 포함). 전부 활성화하고 정책 적용, 실결제 테스트로 정상 확인함.
발견했지만 아직 안 고친 것: external_customers owner_id 컬럼 부재, treatment_charts의 external_customer_id 컬럼명 불일치, /my/charts 조회조건 불일치, user_behavior_logs 컬럼명 불일치.

## 2. 원장 로그인 버그 수정 (완료)
1. "존재하지 않는 원장님 콘솔" 오류 → profiles RLS 강화로 로그인 전 조회가 막혀서 발생. owner_public_profile 공개뷰 신설로 해결.
2. 로그인 후 옛날 라이트버전 뜨는 문제 → 리다이렉트가 ?v=2(구버전)로 가고 있었음. 제거해서 해결.

## 3. 원장 콘솔 반응형 사이드바 (시안 완료, 코드 미작업)
모바일(768px 미만): 햄버거 → 슬라이드 메뉴. PC/태블릿(768px 이상): 좌측 고정 사이드바. 하단 탭바는 완전 제거(사이드바와 중복).
메뉴 4개 섹션: 실시간(홈/오렌상담톡/추천원장소식/예약관리/고객관리), 운영(시술차트/스토어/샵편집/매출리포트), 브랜드(거래브랜드제품), 파트너·설정(구독관리/AI학습).
홈 메인 KPI: 오늘예약/스토어등급/이번달 순수익(판매수수료%는 노출 안 함).
우측 패널(PC/태블릿, 5개 카드): 등급게이지, 내매출(관리권/제품 분리), 내가 모집한 원장 랭킹, 추천원장 실시간알림, 리뷰전환매출.

## 4. 스토어 등급 재설계 (확정, 계산로직 없음)
| 등급 | 월매출 기준 | 인기스토어 노출 |
|---|---|---|
| DÉBUT (새싹) | 가입 즉시 | 없음 |
| ESSOR (파워) | 1,000만원 미만 | 주 1회 |
| PRESTIGE (빅파워) | 1,000만~5,000만원 | 주 3회 |
| COURONNE (프리미엄) | 5,000만~1억원 | 매일 |
| EMPIRE | 1억원 이상 | 매일 + 카테고리 상단 고정 |
정책: 수수료 할인 아닌 노출 기회로 혜택. 오프라인 행사는 등급 무관 전원장 공통참여.

## 5. 추천 보상 정책 (완료, DB 반영됨)
| 추천인 역할 | 보상 |
|---|---|
| 고객 | 3,000토스트 |
| 원장/파트너스/브랜드사 | 없음 |
피추천인 1,000P 삭제. 이유: 원장 등은 이미 자기사업으로 보상받아 중복방지, 원장은 토스트 쓸곳 없어 죽은 포인트화 우려.

## 6. 원장-원장 유치 인센티브 (설계완료, 법적확인함)
방문판매법상 후원방문판매는 "직근 상위 1인"에게만 수당 허용, 2단계 이상은 다단계판매로 분류. 아모레퍼시픽 카운셀러가 60년간 이 원칙으로 운영중임을 확인.
| 유치자 | 피유치자 | 보상 |
|---|---|---|
| 원장 | 원장(전문점) | 추천수당(1회성)+매출연동% 지속인센티브(무제한) |
| 원장 | 파트너스(복제스토어330만) | %1회성만 |
| 상위 파트너스(자격보유) | 원장 | 원장-원장과 동일 |
| 일반 파트너스 | 원장/파트너스 | 1회성 유치수당만 |
한 단계 안에서 여러 보상 종류 지급은 법적 문제없음(제한은 단계수이지 종류수 아님).

## 7. 파트너스 유형 정의 (설계완료)
무자본 링크형(초기비용없음, SNS공유) / 유자본 복제스토어형(330만원, 오렌홈 복제운영) / 신규지사장형(브랜드사협의, 기존원장망에 오렌소개).
기존 지사장은 관성 때문에 영입 어려움 → 신규로 지사 딴 사람을 타겟하는 게 저항 적고 효과적.

## 8. 지사장 시스템 큰 그림 (설계완료, 큰 작업)
세 유통패턴: ①브랜드사 직영(시바산·볼라윤) ②브랜드사→지사장→원장(이타카) ③지사장 한명이 여러브랜드 취급(탈라·안나로자·샵벨르·이타카). 한 원장이 브랜드별로 다른 지사장과 거래 가능.
지사장 대시보드 = 브랜드 대시보드(BrandHubContent.tsx) 재사용, 상단에 "취급브랜드 전환 드롭다운"만 추가.
신규테이블: owner_distributor_brand_links (owner_id, distributor_id, brand_id 3중 연결).
가격통제: 오렌 정찰가로 지사장 가격 난립 해결 가능 - 브랜드사 입점 설득포인트.
온라인지사장 개념: 오렌 자체가 시바산 등에게 "온라인 지사" 역할 가능.
브랜드 미입점 대리등록(이타카 사례): 지사장이 자기책임 대리등록, 나중에 정식입점시 "소유자 전환 스위치"로 데이터유지 이관.

## 9. 브랜드 유통방식 전환 정책 (설계 완료)

### 변경 절차
- **확장하는 변경** (직영→혼합 등): 즉시 반영 가능
- **축소하는 변경** (지사장 권한 회수, 실제로 흔한 케이스): **예고 → 유예기간 → 자동전환**의 3단계 절차 필요

### 회수 절차 상세
1. 브랜드사가 "전환 공지" 작성 (예: "2027년 6월부로 본사-원장 직영체제로 전환됩니다") + 전환 예정일 지정
2. 유예기간 동안 기존 구조 유지, 지사장 대시보드에 "D-30" 카운트다운 배너
3. 지정일 도래 시 자동 전환 실행 + 원장 재배정(직영 전환 또는 타 지사장 이관)

### 예방 기능
- 브랜드사가 제품별 최저가 설정
- 지사장이 최저가 아래로 등록 시 저장 차단 또는 본사 알림

## 신규 아이디어 (2026-07-07) — 캠페인 링크 기반 즉시 증정 시스템
- 요약: 앱푸시(가입회원) / 아이코드 SMS(미가입 외부고객)로 캠페인 링크 발송 → 특정 제품 구매 → 원장이 "택배발송완료" 처리하는 시점에 → 증정품 자동 지급 + 재고 차감
- 배경: 대표님이 미쳤나봐요 모드의 확장 — 즉석발송뿐 아니라 구매 전환 시 리워드까지 연결
- 필요한 것:
  1. 재고(inventory) 테이블 신설 (현재 AURAN에 재고 시스템 없음 — 선행 인프라)
  2. 앱 푸시 알림 시스템 현재 존재 여부 확인 필요 (FCM/APNs 연동 여부 미확인)
  3. 미가입 외부고객은 sendIcodeSms 재사용 (find-id/find-password에서 이미 사용 중인 함수)
  4. 원장 콘솔의 "택배발송완료" 처리 로직 위치 확인 필요 (어느 테이블/버튼/API route인지)
  5. 발송완료 처리 시 재고 차감 로직 추가 (결제 웹훅이 아니라 이 지점)
  6. 캠페인/링크 유입 추적 방식 결정 (쿠폰코드 자동적용 vs UTM vs campaign_id) — 어떤 주문이 "이 캠페인으로 들어온 증정 대상"인지 판별 필요
  7. coupons/user_coupons에 증정품 필드 추가 (reward_type/gift_product_id/gift_product_qty)
  8. 동시성 처리 (여러 발송완료 처리가 몰릴 때 재고 0 근접 시 race condition 방지)
- 별도 세션 필요 이유: 재고 시스템 + 푸시 인프라가 AURAN 전체 주문/배송/알림 흐름에 영향을 주는 기초 인프라라, 별도 세션에서 처음부터 설계해야 함
- 다음 세션 시작 시 우선 확인할 것: (1) 푸시 시스템 존재 여부, (2) "택배발송완료" 버튼 실제 위치 — 이 둘 확인 후 범위 재조정
